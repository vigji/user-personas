## Project

Experiments on persona vectors in **user** representations. First aim: reproduce
the role vectors from the assistant-axis paper, then flip the framing from
"model posing as a persona" to "user posing as a persona".

References:
- Paper: "The Assistant Axis: Situating and Stabilizing the Default Persona of
  Language Models", arXiv:2601.10387 (PDF in `references/`).
- Code: https://github.com/safety-research/assistant-axis (role definitions
  vendored in `data/raw/assistant-axis/`).
- Vectors: https://huggingface.co/datasets/lu-christina/assistant-axis-vectors
  (275 role vectors per model: gemma-2-27b, qwen-3-32b, llama-3.3-70b).

Upstream method, in short: system-prompt a model into each of 275 character
roles, record mean response activations, judge role adherence, average
high-adherence activations into per-role vectors; the Assistant Axis is
`mean(default_activations) − mean(role_activations)` and points toward default
Assistant behavior.

## Layout

- `AGENTS.md` — this file; `CLAUDE.md` is a symlink to it (keep them identical —
  never replace the symlink with a copy).
- `references/` — papers (assistant-axis PDF).
- `data/raw/assistant-axis/` — vendored upstream role data; immutable, never
  edited (see its README for provenance).
- `data/processed/` — derived data, regenerated by
  `scripts/build_user_personas.py`:
  - `personas.txt` — the 275 persona names (one per line).
  - `persona_descriptions.json` — persona → upstream one-line description.
  - `user_persona_instructions.json` — persona → 5 instructions adapted to
    define a simulated *user* posing as that persona (instead of a model).
  - `standard_user_requests.json` — 8 ultra-standard, persona-neutral requests
    every simulated user issues in their persona's voice.
- `data/activations/`, `data/weights/` — large artifacts, kept out of git.
